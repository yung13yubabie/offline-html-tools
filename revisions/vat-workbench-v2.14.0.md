# 營業稅工作台 v2.14.0

日期：2026-11-11。新增每期共用備註、每期客戶銷貨收入及關係企業合併付款；依 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 重整全站字級、元件、明暗狀態及資訊層級，保留離線單檔使用與既有通知日期篩選。

## 每期共用備註

期別管理的每一期設定預設一則備註，可新增或移除，最多 20 則、每則 4000 字；舊期別沒有此欄位時，顯示一則空白，不會偷偷改寫舊資料。新期別獨立填寫，不承接前期內容。本期工作會顯示非空白訊息，個別客戶的本期補充事項仍獨立保存。

通知變數包含 `{本期共用備註}`、`{共用備註1}`、`{共用備註2}` 等；刪除的備註對應變數會留空。共用備註作為資料一次帶入，其內的 `{…}` 視為原文，不遞迴解譯，避免意外改寫及大量重複展開。

## 每期銷貨收入

每期、每位客戶獨立保存收入，可從客戶清單或本期工作費用區編輯；通知的插入資料提供 `{銷貨收入}`。允許空白、0、有效千分位及最多兩位小數，最大 999,999,999,999.99。空白顯示尚未填寫，0 保持為 0；顯示與通知都保留實際小數。

收入資料不改變應收款、營業稅、記帳費或其他費用。完整及包含期別工作紀錄的備份會保存收入，單獨客戶庫匯出仍只包含基本資料。

## 關係企業合併付款

付款公司及沖款對象由使用者明確選取，程式不會自動推定關係企業。對象須為同一期適用客戶；每家公司填指定金額。分配合計必須等於原始付款，且不得超過各公司目前尚欠，金額最多兩位小數。

原始收款來源保留一次，每家公司只將自己的分配金額寫入付款紀錄，沿用各自 FIFO 沖銷。付款來源、總額、公司分配與日期都有共同識別；分項不可單獨改寫或刪除。需要修正時撤銷整筆，再重新登記；撤銷來源紀錄保留，全部分項以單一交易撤回。

登記與撤銷都讀取最新資料，再於同一 IndexedDB 交易內驗證、計算及寫入；不允許只存下一家公司。不一致的合計、來源、沖銷紀錄或已鎖定期別會拒絕，錯誤時保留填寫內容。影響後期已儲存沖銷或已結束後期餘額時，也會檢查，不會靜默改寫鎖定資料。

部分匯出會擴充為完整的合併付款關聯資料，包含必要客戶和期別；還原及合併前會驗證來源與各分項一致。舊資料沒有合併付款時仍可使用原本的付款方式。

## 全站介面與狀態修復

公司名稱下方改為有標籤的資料組：本期地址、聯絡人、本期記帳費、客戶庫預設記帳費；修正原畫面將本期快照誤稱為客戶庫費用的來源問題。地址及聯絡資料可換行，不縮成難讀的小字；全站沿用一致的卡片、表單、間距、按鈕及明暗配色。螢幕樣式獨立於紙張樣式。

子代理交叉查核並修正：期別管理繞過未儲存提示、無效表單提早關閉、儲存等待時輸入消失、同一期的 `1`／`01` 重複建立、小數被整數格式四捨五入、共用備註遞迴展開，以及不完整合併付款備份和重複分項。實測紀錄見 [TEST_REPORT.md](../TEST_REPORT.md)。

## 下載與維護

[vat-workbench.html](../apps/vat-workbench.html) 即為 v2.14.0 成品，進入 GitHub 檔案頁按 **Download raw file**。原有資料與標註備份方式維持；新版欄位隨原資料集保存，未新增外部執行依賴。

來源在 `vat/`，以 `python3 tools/embed-vat.py` 內嵌；`--check` 核對成品。設計來源、採用與未採用的技能建議記錄於 [設計規則](../design-system/vat-workbench.md)。本輪測試只使用合成資料，不將使用者截圖的客戶資料加入公開範例。

本機 localhost HTTP 的 49 組 Chromium 檢查、15 項期別／收入核心與 51 項合併付款核心，以及既有純回歸均通過。最後追加的舊費用 ID 真實資料庫案例也通過。GitHub 離線開檔結果將記錄於 [TEST_REPORT.md](../TEST_REPORT.md)；未實測其他瀏覽器、真實手機或同步多使用者壓力。
